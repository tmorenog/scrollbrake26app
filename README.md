# BreakScroll

BreakScroll is an iPhone app that turns automatic scrolling into a deliberate choice. Someone uses a selected app for X minutes. Then the app is shielded, and continuing takes a short pause and a quick challenge. That earns another X minutes, and the cycle repeats. It works for an adult limiting their own phone (Self-Control Mode), and for a parent setting rules for a child in their Family Sharing group (Family Mode).

- Why the design looks like this, checked against Apple's current docs: [`SCREEN_TIME_FEASIBILITY.md`](SCREEN_TIME_FEASIBILITY.md)
- How the repeating X-minute loop works, plus on-device experiments: [`REPEATING_INTERVALS.md`](REPEATING_INTERVALS.md)

## Layout

```
BreakScrollCore/                 Swift package: rules, schedules, challenges, the
                                 intervention state machine, sync merging, shield copy.
                                 Foundation only, so it builds and tests anywhere.
scrollbrake26app/
  scrollbrake26app.xcodeproj     Generated by tools/generate_xcodeproj.py
  BreakScroll/                   The app (SwiftUI): onboarding, home, rule editor,
                                 intervention screen, parent preview, DEBUG panel
  Shared/                        Compiled into the app and all three extensions:
                                 App Group store, Screen Time calls, engine coordinator
  DeviceActivityMonitorExtension/  Turns threshold and interval callbacks into engine inputs
  ShieldConfigurationExtension/    Wording on the system shield
  ShieldActionExtension/           Continue / I'm Done on the shield
  scrollbrake26app/              OLD app sources. Not built any more; safe to delete.
tools/generate_xcodeproj.py      Regenerates the project (folder-synced groups)
```

Every target builds its own folder plus `Shared/`, and links `BreakScrollCore`. New `.swift` files are picked up automatically. Re-run the generator only when targets, folders or build settings change.

## Testing

Run these before any device build. They need a Swift 6 toolchain on Linux (the simulation's fake frameworks reuse Apple's module names, so it doesn't build on macOS). The cloud container used for development has one.

| Command | What it checks |
|---|---|
| `cd BreakScrollCore && swift test` | 54 tests: the engine, challenges, schedules, escalation, sync merging, shield copy and passcode lockout, plus 300 × 400 random-input runs checking safety invariants after every step |
| `cd Simulation && swift test` | 30 scenarios on a **simulated iPhone**. The real `Shared/`, extension and `AppModel` sources run against fake Screen Time frameworks that behave as Apple documents. Covers the MVP loop, I'm Done, active hours, midnight, the daily cap, failures, multiple rules, categories, revocation, edits, escalation, crash recovery and a 40-seed, 3-day soak |
| `python3 tools/validate_project.py` | Extension points, principal classes, entitlements vs the App Group, and project file references |

Mutation testing: 14 deliberately planted bugs (failed re-arm unlocking, counting past usage, missing generation checks, unshielding early, and others) were each caught by these suites.

**What these can't prove**, so it still needs a real iPhone:
- that the SwiftUI screens compile (they were reviewed against Apple's docs line by line, but never compiled)
- Apple's actual runtime behavior, especially experiment E1 (restarting monitoring resets usage) and E3 (the parent's picker shows the child's apps).

The simulation assumes Apple's documented behavior. If E1 shows otherwise on a device, the simulation is where to model the real behavior first.

## Building for a device

**Requirements:**
- Xcode **26.5 or later**. The Shield Action extension refers to `ShieldActionResponse.openParentalControlsApp`, which first appears in the iOS 26.5 SDK.
- A physical iPhone on iOS 17.4 or later. Screen Time APIs don't work in the Simulator.
- An Apple Developer account. Development builds can use the Family Controls capability right away. App Store distribution needs Apple's approval for **each** of the four bundle IDs.

**Steps:**
1. Open `scrollbrake26app/scrollbrake26app.xcodeproj`.
2. For **all four targets** (scrollbrake26app, DeviceActivityMonitorExtension, ShieldConfigurationExtension, ShieldActionExtension), go to Signing & Capabilities and choose your Team.
3. Check that all four targets list **Family Controls** and **App Groups** with `group.com.scrollbrake26app.shared`. If that group ID is taken for your team, change it in all four `.entitlements` files and in `Shared/AppGroup.swift`.
4. Select the `scrollbrake26app` scheme and your iPhone, then Run. The app appears on the Home Screen as **BreakScroll**.

## On-device test 1: the repeat loop (one iPhone, Self-Control Mode)

This is experiment E1 and blocks everything after Phase 7.

1. Launch the app and choose **Just for me**, then **Allow Screen Time Access**. Confirm with Face ID.
2. Tap **Add Rule** and choose one app you can test with. Save.
3. Go to **Developer** (DEBUG builds only). For the rule, set Threshold to **1 minute** and Pause to **5s**.
4. On your Mac, open Console.app, select the iPhone and filter on subsystem `com.breakscroll`.
5. Use the chosen app for a little over a minute.
   - **Expect:** `threshold rule=… gen=N`, then the shield ("Time for a quick break") appears.
6. Tap **Continue**.
   - On iOS 26.5+, BreakScroll opens.
   - On earlier iOS, tap the notification to open it.
   - You'll see a 5-second pause, then a math problem.
7. Answer correctly.
   - **Expect:** `armed rule=… gen=N+1 threshold=60s`, then `shield removed`.
8. **Success:** the app works again, and the shield returns only after about one more minute of use, not straight away. Repeat three times.
9. Also try **I'm Done** on the shield. The app should close, and the shield should stay up.

If the shield comes back within seconds of unlocking, usage from before the re-arm is still being counted. Record the iOS version in the table in `REPEATING_INTERVALS.md`.

## On-device test 2: Family Mode (two iPhones)

The child's iPhone must be signed in with a child Apple Account in your Family Sharing group.

1. **Child's iPhone:** choose **This is my child's iPhone**, then **Set Up Family Controls**. A parent signs in with their Apple Account when asked.
   - **Expect:** BreakScroll can no longer be deleted on that iPhone, and iCloud can't be signed out.
2. **Child's iPhone:** **Add Rule**. Create the parent passcode, choose the app, and use the debug panel for a 2-minute threshold and 10-second pause, as in steps 5–8 above.
3. **Parent's iPhone:** choose **I'm a parent, on my own iPhone**, then **Choose from Your Child's Apps**. This is experiment E3.
   - **Success:** the picker lists the child's apps, not the parent's own.
   - Record what you see, because it decides how Phase 10 picks apps.

Changing rules from the parent's iPhone (MVP step 16–17) needs CloudKit sync, which is Phase 10.

## Privacy

BreakScroll stores only its own counts of breaks, on the device. It never sees which apps someone uses or what's in them. There are no analytics SDKs. "Delete BreakScroll Data" on the Home screen removes rules and history.
